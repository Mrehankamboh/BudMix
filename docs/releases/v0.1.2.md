BudsLink 0.1.2 — preview. Hear your laptop and your phone in the same Bluetooth buds on Windows 11.

## Download

| File | What it is |
|---|---|
| `BudsLink-0.1.2-windows-x64-setup.exe` | Installer for your user only: Start menu entry and uninstaller, no admin prompt |
| `BudsLink.exe` | The app as a single file, no installer |
| `SHA256SUMS.txt` | Checksums for both |

The build isn't code-signed: the first time, Windows shows *"Windows protected your PC"*. Click **More info → Run anyway**. On a PC with Smart App Control on, Windows blocks unsigned apps.

## What's in it

- **Buds:** auto-connect and reconnect, the buds become the default output (your previous output comes back), test beep, a warning when an app drops the buds to call quality (HFP).
- **Phone over Wi-Fi:** a built-in Miracast receiver — tap **Cast → BudsLink** on the phone. New phones need your OK once; an optional window shows the phone's screen.
- **Phone over Bluetooth:** the automatic fallback. *Auto* never plays the same phone twice.
- **Per-source volume:** buds, laptop, phone over Wi-Fi, phone over Bluetooth.
- **Setup check** with one-click fixes, diagnostics, light and dark, start with Windows.

### Changes since 0.1.0

- The receiver no longer switches itself off when the phone's direct Wi-Fi link appears (Windows marks that link Public).
- New settings window: the buds at the top, and open, uncluttered sections.

## Known issues

- **Cast connects but there is no sound:** the phone's sound arrives over the direct Wi-Fi link, which Windows treats as a Public network, and the firewall rule from the setup check only covers Private networks. Until the app handles this, allow BudsLink on that link yourself, in PowerShell **run as administrator**:
  ```powershell
  New-NetFirewallRule -DisplayName "BudsLink (phone cast link)" -Direction Inbound -Action Allow -Profile Public -RemoteAddress LocalSubnet -Program "$env:LOCALAPPDATA\BudsLink\budslink.exe"
  ```
- **Phone over Bluetooth fails with error 0x8007001F** on some phones: disconnect the phone from your buds, then turn Bluetooth off and on, on the laptop and on the phone.
- Hardware testing is still in progress; see `docs/HARDWARE_TESTING.md`. Latency: about 0.1–0.3 s for casting plus 0.15–0.25 s for Bluetooth to the buds.
