BudMix 0.2.0 — preview. Hear your laptop and your phone in the same Bluetooth buds on Windows 11. This is the same app as BudsLink 0.1.2, under its new name.

## Download

| File | What it is |
|---|---|
| `BudMix-0.2.0-windows-x64-setup.exe` | Installer for your user only: Start menu entry and uninstaller, no admin prompt |
| `BudMix.exe` | The app as a single file, no installer |
| `SHA256SUMS.txt` | Checksums for both |

The build isn't code-signed: the first time, Windows shows *"Windows protected your PC"*. Click **More info → Run anyway**. On a PC with Smart App Control on, Windows blocks unsigned apps.

## What's new

- **New name and logo:** BudMix. The phone's Cast list now shows **BudMix**.
- A settings window with the buds at the top and open, uncluttered sections.

## Coming from BudsLink

BudMix installs as a new app, next to the old one:

1. Quit BudsLink from the tray and uninstall it in Windows Settings → Apps.
2. Install BudMix and run the setup check again. Settings and allowed phones start fresh.
3. The old firewall rules point at the old program, so add them again (see below).

## Known issues

- **Cast connects but there is no sound:** the phone's sound arrives over the direct Wi-Fi link, which Windows treats as a Public network, and the firewall rule from the setup check only covers Private networks. Until the app handles this, allow BudMix on that link yourself, in PowerShell **run as administrator**:
  ```powershell
  New-NetFirewallRule -DisplayName "BudMix (phone cast link)" -Direction Inbound -Action Allow -Profile Public -RemoteAddress LocalSubnet -Program "$env:LOCALAPPDATA\BudMix\budmix.exe"
  ```
- **Phone over Bluetooth fails with error 0x8007001F** on some phones: disconnect the phone from your buds, then turn Bluetooth off and on, on the laptop and on the phone.
- Hardware testing is still in progress; see `docs/HARDWARE_TESTING.md`. Latency: about 0.1–0.3 s for casting plus 0.15–0.25 s for Bluetooth to the buds.
